## Design Specificity Verdict

视觉已经具备墨风的蓝白舞台识别，但设置体系仍是通用后台配置器：把供应商、模型、价格、能力和阶段路由平铺给作者。品牌表达集中在“乾、存、契”等徽章，反而没有帮助作者理解“怎样让创作可用”。自动 detector 对 `SettingsView.vue` 返回 0 条，说明问题不是常见样式反模式，而是信息架构和交互层级。

## Overall Impression

设置功能本身可用，数据保护也有基础，但入口和宿主错误：稳定、复杂、可深链的配置被塞进全局弹窗，内部再叠加模型选择和确认层。最大机会是复用已有 `/settings` 页面，删除全局设置弹窗分支。

## What's Working

- 文本生成、记忆检索、语音朗读、阶段路由四个能力边界已有清晰代码结构。
- 保存反馈、未保存确认、删除保护和 tab 键盘语义已经存在。
- 供应商、默认模型和阶段路由均有真实运行时消费者，没有发现可以安全断言为死字段的用户配置。

## Priority Issues

### [P1] 页面与弹窗双宿主

`SettingsView` 同时服务 `/settings` 与 `AppShell` 全局弹窗；弹窗模式禁用 URL tab 同步，又在外层复制保存和关闭逻辑。应删除全局弹窗宿主，账户菜单直接导航 `/settings`。

### [P1] 多层对话与滚动上下文

设置大弹窗内继续 Teleport 模型选择器，未保存与删除确认还会形成后续对话层。桌面返回路径复杂，移动端存在双滚动和焦点恢复风险。模型选择应改为页面内展开或同层抽屉；只为破坏性确认保留 dialog。

### [P1] 导航混合个人、AI 与管理员职责

用户菜单同时放系统管理、提示词用量、个人 AI、密码和退出。应只保留 AI 设置、账户与安全、管理后台（管理员）和退出；提示词用量归入管理后台。

### [P2] 技术配置暴露过多

首次配置需要的只是供应商连接、文本主模型和检索模型。模型定价只服务成本统计，阶段路由属于高级覆盖，运行指标与刷新属于诊断。它们应进入“高级”或按需显示，不应与首次可用路径同权。

### [P2] 重复入口和术语

“个人设置 / AI 能力中心 / 能力配置面板”指同一体系；空状态和顶栏重复“新增供应商”，启停同时存在卡片快捷入口和编辑表单。应统一名称与唯一主入口。

## Persona Red Flags

- 新手作者：无法快速判断先配置供应商、模型还是阶段路由，容易在基础可用前进入高级覆盖。
- 高级自托管作者：无法用 URL 直接回到弹窗内分区，配置核对被装饰和重复操作拖慢。
- 键盘与移动用户：嵌套 dialog、焦点恢复不明确和双滚动会让退出路径不可预测。

## Recommended Information Architecture

全局账户菜单只导航，不承载大型工作流：AI 设置、账户与安全、管理后台（管理员）、退出登录。`/settings` 页面先呈现“连接供应商 → 选择文本主模型 → 选择检索模型”的可用性路径；TTS、模型定价与阶段路由进入高级区。模型选择和供应商编辑在页面内完成，破坏性操作才使用确认对话框。

## Minor Observations

- 当前设置弹窗标题只写“个人设置”，与内部内容不符。
- 阶段路由默认应表达为“继承主模型”，只突出显式覆盖项。
- TTS 音色和语速已经归属朗读控件，不应重新塞回模型设置。
- 浏览器打开模型选择器时出现 Vue 运行时告警：`pending-tts-model-name` 被传入但未声明为组件 prop，说明组件接口已有漂移。

## Questions to Consider

- 是否接受彻底取消全局设置弹窗，统一使用 `/settings`？
- 是否把“基础可用”和“高级调优”作为设置页的首要层级？
- 管理员功能是否全部从个人账户菜单移入 `/admin`？
