**设计特异性判断**

“管理只读”标记、故事蓝图带、档案抽屉和纸面内容延续了墨风的管理巡检语境。它比普通详情多出明确返回与移动导航，跨设备完整性更好；但当前页的品牌可信感被假 0 数据和缺失章节入口直接破坏。

静态 detector 对 `AdminNovelDetail.vue`、共享详情壳和详情组件目录为 0 项。浏览器 axe 桌面发现 3 类违规：更新时间 3.41:1、缺 H1、内部滚动区域不可键盘聚焦；移动发现后两类。390px 页面宽度正常，无横向溢出。

**整体印象**

这是一个视觉上完成度较高、行为上却没有满足“内容巡检”的管理详情页。先修数据合同与章节入口，再处理标题语义和对比度；继续美化概览没有意义。

**做得好的地方**

- 移动端有明确 44px 抽屉开关，关闭后正文单列可读，未复现普通详情的导航不可达。
- “管理只读”持续可见，编辑弹窗和新增章节能力不会在 admin 模式渲染。
- 返回按钮稳定回到 `/admin?tab=novels`，管理路径闭环清楚。

**优先问题**

1. **[P1] 管理概览用 0 填补接口缺失字段，显示假数据**
   - 影响：管理员看到角色 0、章节 0/0、未开始，却在全局栏同时看到 75/100；可能错误判断项目为空或生成失败。
   - 证据：admin overview 接口只返回标题、摘要、类型、风格、语调等字段，没有 character_count、completed_chapters、total_chapters；UI 用默认 0 渲染。
   - 修正：管理 overview 合同直接返回真实统计，或并行读取管理项目摘要；字段缺失时显示“未提供/读取失败”，绝不能默认为 0。
   - 建议命令：`$impeccable harden`

2. **[P1] 管理员无法进入章节正文巡检**
   - 影响：后台小说项目页说明要“进入详情巡检内容”，但导航只有章节大纲，没有章节正文、版本和评审；核心治理任务无法完成。
   - 证据：`ChaptersSection.vue` 已支持 `isAdmin` 并调用管理员章节 API，组件映射也存在，但 `sections` 清单未包含 `chapters`。
   - 修正：把“章节内容”加入 admin 导航，使用现有只读 `ChaptersSection`；不要新建第二套章节查看器。
   - 建议命令：`$impeccable clarify`

3. **[P2] 当前分区不写入 URL**
   - 影响：切到世界设定后 URL 不变，刷新回项目概览，也无法把具体巡检位置交给其他管理员。
   - 修正：复用既有 `section` query，在切换时 `router.replace`；后台和普通详情使用同一实现。
   - 建议命令：`$impeccable harden`

4. **[P2] 标题层级重复且缺 H1**
   - 影响：项目名在 topbar 与概览带重复为两个 H2，页面没有 H1；屏幕阅读器结构不清。
   - 修正：topbar 项目名作为唯一 H1，概览带改为普通文本或隐藏重复标题；内部区块维持 H3/H4。
   - 建议命令：`$impeccable typeset`

5. **[P2] 内部滚动区不可键盘聚焦，更新时间对比不足**
   - 影响：键盘用户可能无法滚动内容面；12px 更新时间仅 3.41:1。
   - 修正：滚动容器设置 `tabindex="0"` 和可访问名称，并确保焦点环可见；更新时间使用至少 4.5:1 的正文 token。
   - 建议命令：`$impeccable audit`

**角色风险**

- 内容巡检管理员：无法查看章节正文、版本或评审，只能看大纲。
- 运营管理员：0/0 假数据与全局 75/100 冲突，无法判断哪个口径可信。
- 键盘用户：内部滚动区不能聚焦，长梗概和分区内容难以浏览。
- 协作管理员：无法分享“世界设定/章节内容”等具体分区链接。

**次要观察**

- 三个完成标记 span 使用无效 `aria-label`；可见“成”之外应提供屏幕阅读器文本或放到有语义的状态容器。
- 桌面首次加载会先显示《加载中…》、0/0 和未开始，应改为结构骨架而非假统计。
- admin 模式的“进入写作台”调用路径拿不到普通项目实体，当前顶栏没有呈现该动作；保持只读是合理的，不必强行增加写作入口。
- 未查看或修改任何项目数据，未调用分析/生成能力。

**值得追问**

- 内容巡检的最小范围是否应包括正文、版本、评审、生成状态和错误 trace？

- 管理只读页是否需要显示作者与项目 ID，方便权限和审计定位？
