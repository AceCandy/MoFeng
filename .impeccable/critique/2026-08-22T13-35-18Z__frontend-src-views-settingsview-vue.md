**设计特异性判断**

“AI 能力中心”、能力就绪印、文本/记忆/朗读/枢路四分区和宋楷纸面符合墨风的安静书案气质。整体不是通用 API Key 设置页，尤其把模型配置与创作阶段联系起来很有产品特异性。薄弱处是供应商卡片与密集 select 阵列仍像运维后台，缺少“这项配置会影响哪一步写作”的可理解结果视图。

静态 detector 对 `SettingsView.vue` 与 `llm-settings` 目录为 0 项。桌面 axe 发现 2 类违规：10 个低对比删除操作和缺少 H1；移动阶段路由发现缺 H1。另有无角色 div 使用 `aria-label`、3 个 `aria-controls` 指向未挂载对话框等 incomplete 信号。

**整体印象**

概览层、主模型摘要和四分区导航已经能降低配置焦虑。最大风险不是视觉，而是设置容器把每个 tab 当成可销毁的临时实例，导致用户在最复杂的阶段路由页做完修改后，一次普通切换就全部丢失。

**做得好的地方**

- 首屏直接给出能力是否就绪、主文本模型、主检索模型和供应商启用数，状态反馈明确。
- 桌面与 390px 均无横向溢出；四个 tabs 支持 roving tabindex、方向键、Home/End。
- API Key 在卡片中以掩码展示，供应商、模型、主模型和能力类型分层清楚。

**优先问题**

1. **[P1] 阶段路由未保存修改会在切换分区时静默丢失**
   - 影响：用户可能逐项设置数十个创作阶段，点击“文本生成”查看模型后全部重置；之后关闭弹窗也不会提示。
   - 根因：四个分区用 `v-if / v-else-if` 各自创建 `PersonalModelRouting`；`selectSettingsSection` 直接换 active 值并销毁旧实例。`isDirty` 只读取当前 ref，新分区重新加载后为干净状态。
   - 修正：最小可靠方案是在分区切换前读取当前 `isDirty` 并确认“保存/放弃/取消”；不要先切换再判断。独立页离开与弹窗关闭共用同一拦截逻辑。
   - 建议命令：`$impeccable harden`

2. **[P1] 阶段路由在移动端是约 6324px 高的下拉框长墙**
   - 影响：几十个阶段、8 个重复模型选项和 H4/H5 分组让用户难以理解继承关系，也难以确认自己改了哪些项。
   - 修正：默认只展示显式覆盖项和分组摘要；“使用主模型/检索模型”作为继承状态，按“正文工作流、其他功能”逐组展开；在顶部显示“已覆盖 N 项/未保存 N 项”。
   - 建议命令：`$impeccable distill`

3. **[P1] 删除供应商与删除模型文字低于 WCAG AA**
   - 影响：3 个供应商删除按钮约 3.41:1，7 个模型删除按钮约 4.13:1，均低于 12px 正文的 4.5:1。
   - 修正：删除文字使用更深的 error token，或保留普通高对比文字、仅在 hover/focus/确认态使用错误色；不要靠变淡来弱化危险操作。
   - 建议命令：`$impeccable colorize`

4. **[P2] 设置页没有 H1，分区状态也不写入 URL**
   - 影响：屏幕阅读器缺少页面级入口；切到“阶段路由”后地址仍是 `/settings`，刷新和复制链接都回到“文本生成”。
   - 修正：主标题改为唯一 H1；独立页用 `?section=routes` 同步当前 tab。弹窗模式无需改 URL，但应复用相同 section resolver。
   - 建议命令：`$impeccable audit`

5. **[P2] 弹窗触发器和状态摘要存在 ARIA 关联错误**
   - 影响：3 个“拉取模型”按钮声明 `aria-controls=model-picker-*`，但关闭时目标节点不存在；readiness div 使用无效 aria-label。
   - 修正：对话框常驻 DOM 隐藏，或仅打开时设置 `aria-controls`；readiness 使用 `<section aria-label>` 或可见标题，不给普通 div 添加无效名称。
   - 建议命令：`$impeccable audit`

**角色风险**

- 谨慎配置者：修改十几条阶段路由后切 tab，工作静默丢失且无法恢复。
- 移动端作者：需要滚动 6000px 以上才能浏览完整路由，难以比较相邻阶段。
- 低视力用户：危险操作恰好使用最低对比文字，识别成本更高。
- 首次配置者：知道“能力就绪”，但不知道每条覆盖会增加多少成本或改变哪一步输出。

**次要观察**

- 独立 `/settings` 没有全局“存”按钮；供应商/模型多为自动保存，阶段路由却手动保存，应该在顶部明确说明当前分区的保存模式。
- “查看运行指标”使用原生 details/summary，44px 目标和焦点态良好。
- 主标题目前是 H2，面板从 H3 开始；改 H1 后现有层级可直接保留。
- 未打开供应商编辑、模型拉取或定价弹窗，未查看或修改任何密钥、模型和路由数据。

**值得追问**

- 用户真的需要逐项覆盖几十个阶段，还是 80% 场景只需“快速/平衡/高质量”三组策略？
- 自动保存与手动保存能否在分区标题旁直接标明，而不是让用户通过按钮存在与否猜测？
- 阶段路由最有价值的视图是“阶段→模型”，还是“模型→承担哪些阶段”？
