**设计特异性判断**

页面具有鲜明的“墨风”识别：夜案、稿纸、朱砂与竖排题字形成完整视觉语言，不是可替换到任意 SaaS 的模板。问题是这种特异性占据了桌面约 60% 的视觉重量，移动端也先展示大段品牌区，回访作者的“立即续写”任务反而退居次位。

自动源码检测为 0 项；浏览器 axe 确认 3 项同源地标问题，根因是 `AuthLayout.vue` 与 `Login.vue` 同时输出 `<main>`。浏览器覆盖层报告 7 组反模式信号，其中渐变背景、装饰碑字导致的低对比和溢出信号存在误报，不作为确定缺陷；源码与实屏共同支持的视觉层级问题保留。

**整体印象**

第一眼很有记忆点，表单基础可用性也扎实，但“可信、直接地完成登录”还不够强。最大机会不是继续加装饰，而是删掉无效控件、修正语义地标，并让登录任务更快进入视线。

**做得好的地方**

- 表单有显式标签、autocomplete、密码显示、可见焦点、加载态和 `role="alert"` 错误反馈。
- 桌面与 390×844 移动端均无明显横向溢出或内容裁切，按钮触控尺寸基本合格。
- 墨色、朱砂、宣纸与写作术语保持统一，品牌辨识度高。

**优先问题**

1. **[P1] “记住我”是无效控件**
   - 影响：用户勾选后行为不变，直接损害信任。
   - 证据：`rememberMe` 只在 `Login.vue` 本地绑定；登录请求不读取它，认证 token 无条件写入 `localStorage`。
   - 修正：最小且安全的方案是删除该控件。只有产品明确需要“临时会话”时，才新增 session/local 两套存储语义。
   - 建议命令：`$impeccable harden`

2. **[P1] 页面存在两个 `<main>` 地标**
   - 影响：读屏器地标导航含糊，违反页面只能有一个主内容地标的语义预期。
   - 证据：`AuthLayout.vue` 外层和 `Login.vue` 根节点均为 `<main>`；axe 报告 duplicate/非顶层/不唯一 main。
   - 修正：共享布局保留 `<main>`，登录页根节点改成普通容器；或反过来，但只保留一个。
   - 建议命令：`$impeccable audit`

3. **[P2] 登录失败后没有恢复路径**
   - 影响：忘记凭据的用户只能反复尝试，创作连续性被打断。
   - 证据：当前路由与表单都没有密码恢复入口，错误只提示检查用户名和密码。
   - 修正：在未实现重置流程前，提供明确的“联系管理员恢复账户”说明；已有后端恢复能力时再链接到真实流程，避免创建死链接。
   - 建议命令：`$impeccable harden`

4. **[P2] 品牌装饰压过登录主任务**
   - 影响：回访作者需要跨越大面积品牌区才能定位表单；移动端表单被推到首屏下半段。
   - 修正：桌面缩小碑字与品牌簇并将表单靠近视觉中心；移动端只保留品牌名与一句说明，压缩头部高度。
   - 建议命令：`$impeccable distill`

5. **[P2] 认证术语过度隐喻**
   - 影响：“笔名 / 口令 / 入卷续写”对首次用户不如“用户名 / 密码 / 登录”直接。
   - 修正：改为“用户名（笔名）”“密码（口令）”“登录并继续写作”，把诗性留给标题与装饰。
   - 建议命令：`$impeccable clarify`

**角色风险**

- 回访作者：无效的“记住我”和缺失的恢复路径会让登录行为不可预测，直接打断续写。
- 首次用户：需要先把“笔名/口令/入卷”翻译成账户概念，主按钮识别速度较慢。
- 移动端作者：品牌头部占据较大首屏空间，软键盘出现后需要更多滚动才能确认上下文。

**次要观察**

- 加载文案使用 `...`，应统一为中文省略号 `…`。
- “记住我”复选框缺少 `name`，但建议直接删除无效控件，不为死控件补属性。
- Linux DO 开启、注册关闭、真实超时和成功跳转状态尚未覆盖。

**值得追问**

- 登录页的第一目标是展示品牌，还是让回访作者 5 秒内回到写作台？
- 既然 token 当前总是持久化，“记住我”是否还有存在理由？
- 自托管场景下，账户恢复应该由站内流程承担，还是明确引导联系管理员？
