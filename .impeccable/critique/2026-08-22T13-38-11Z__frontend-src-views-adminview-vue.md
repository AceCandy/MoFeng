**设计特异性判断**

六分区的题签、方印和纸面延续墨风身份，管理任务也基本按平台治理逻辑组织。具体内容仍较像通用 CRUD 后台，尤其系统配置表把 key/value 直接平铺，没有把“托管项、普通项、敏感项”转化成不同的操作与可见性规则。

静态 detector 对 `AdminView.vue` 与 admin 组件目录为 0 项。浏览器 axe：数据总览 1 类违规（缺 H1）；用户管理 4 类违规，包括 3 个无名称状态开关、5 个不合法的 role=button、2 个列表结构错误及缺 H1。390px 无横向溢出，但 Prompt 移动页有约 45 个按钮，信息密度明显过高。

**整体印象**

后台的导航和卡片骨架已经统一，但治理工具必须先保证安全和状态可信。当前最严重的问题是把秘密值当普通配置展示；其次是“点一下立即生效”和“切一下静默丢失”两类缺少保护的管理操作。

**做得好的地方**

- 六个顶级分区使用 URL `?tab=` 同步状态，刷新和分享可保留当前位置。
- 用户、Prompt、项目、日志、配置均有统一标题、指标摘要和内容区，学习成本低。
- 用户、Prompt、日志和配置的删除动作都使用确认弹层；管理员账号不可直接删除。

**优先问题**

1. **[P0] 系统配置把敏感值以明文返回并渲染**
   - 影响：任何能打开管理后台的人、屏幕共享、录屏、浏览器扩展和辅助技术都能读取 API Key、SMTP 密码、OAuth 客户端密钥等秘密；这不是视觉问题，而是凭证泄露。
   - 证据：系统配置表的“值”单元格与 accessibility tree均出现完整敏感值。
   - 修正：后端按 key 的敏感元数据永不返回原值，只返回 `has_value` 与固定掩码；编辑时使用空输入表示“不修改”，只有用户输入新值才替换。前端禁止把敏感值写入 DOM、title、日志或错误消息。现有已暴露凭证应轮换。
   - 建议命令：`$impeccable harden`

2. **[P1] Prompt 编辑没有脏状态保护**
   - 影响：管理员修改正文、标题或标签后，点击另一模板或其它后台 tab 会直接覆盖本地表单，无法恢复。
   - 证据：`selectPrompt` 无条件重写 `editForm`；`AdminView.selectSection` 直接替换异步组件，没有 before-leave 检查。
   - 修正：在选择另一 Prompt 或离开分区前比较当前表单与原始值，提供“保存/放弃/取消”；不要额外引入全局状态库。
   - 建议命令：`$impeccable harden`

3. **[P1] 用户启用/禁用开关即时写入且无名称、无确认**
   - 影响：误触可立即阻止用户登录；屏幕阅读器只听到无名称 switch，不知道操作对象。
   - 修正：为开关设置“启用/禁用用户 {username}”可访问名称；禁用需要确认并说明“历史项目保留、登录将受限”，启用可直接执行或提供短暂撤销。
   - 建议命令：`$impeccable audit`

4. **[P1] 加载状态先展示真实样式的 0 数据**
   - 影响：慢请求期间数据总览、用户、Prompt、小说项目和配置都显示 0/暂无，管理员可能误判数据已丢失；墨晕 loading 遮罩又降低整页对比。
   - 修正：首次加载用结构骨架或“正在读取”占位，不渲染 0；刷新时保留上次数据并只在局部显示同步状态。
   - 建议命令：`$impeccable harden`

5. **[P2] 移动端 Prompt 列表与编辑器缺少压缩导航**
   - 影响：30 多个模板按钮和编辑区在单列中堆叠，移动快照有约 45 个按钮；找模板依赖长滚动。
   - 修正：增加本地搜索与标签筛选；移动端先显示列表，选中后进入编辑视图并提供明确返回，不同时堆叠两块长内容。
   - 建议命令：`$impeccable adapt`

**角色风险**

- 安全管理员：打开配置页即把生产凭证暴露给 DOM 与屏幕共享。
- 内容运营：编辑长 Prompt 后误切模板，修改静默丢失。
- 用户支持人员：无名称开关增加禁用错账号的概率。
- 移动值班管理员：Prompt 与配置长列表难以快速定位并安全操作。

**次要观察**

- 全后台没有页面级 H1，当前分区标题多从 H2/H3 开始。
- 用户统计筛选卡用 article/li 加 `role=button`，axe 判定不合法；直接使用 button 包裹可见内容。
- Prompt 名称主要是内部英文 key，缺少搜索与用途分组；标签统计目前多数为空，分类价值没有发挥。
- 系统配置同时提供快捷卡片和原始表格两套编辑入口，托管项虽有提示，但仍允许直接删除，权限边界不够强。
- 未打开或提交任何新增/编辑/删除表单，也未切换用户状态或系统配置。

**值得追问**

- 哪些配置必须永久不可回显，哪些只需对普通管理员隐藏？最好由后端元数据明确，不靠前端 key 名猜测。
- 用户禁用是否需要记录原因和审计日志，而不是单一布尔开关？
- Prompt 管理的首要检索维度是名称、用途、调用阶段还是最近修改？
