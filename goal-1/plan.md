# 墨风前端技术质量审计与修复方案

本项目旨在通过 `$impeccable audit` 机制，对“墨风（MoFeng）” AI 辅助写作控制中心的前端代码进行全面的技术质量审计，并针对无障碍性（Accessibility）、性能（Performance）、响应式设计（Responsive Design）、主题（Theming）及反模式（Anti-Patterns）等维度的缺陷进行逐一修复，最终重新评估以实现健康评分的显著提升。

## 需求分析

1. **全面审计**：遵循 `reference/audit.md` 规定的五大维度，利用静态分析和浏览器运行态分析相结合的方式，为项目当前状态生成第一版审计报告（`goal-1/audit_report_v1.md`），量化初始健康评分。
2. **渐进修复**：根据首版审计报告中识别出的问题，确定优先级（P0 阻塞至 P3 抛光）与推荐的 `impeccable` 工具指令，制定具体修复清单。
3. **回归验证**：修复后重新执行审计，生成第二版审计报告（`goal-1/audit_report_v2.md`），对比评分变化，量化提升效果。
4. **风骨守护**：确保所有无障碍和响应式修改皆不破坏 `DESIGN.md` 中定义的“徽墨熟宣、古籍双边与朱砂印鉴”中国风设计系统硬性规则（Do's and Don'ts）。

## 潜在风险与应对策略

1. **服务启动与依赖问题**  
   - *风险*：在无人值守的 goal 模式下，启动前后端服务可能遇到端口冲突、进程挂起或依赖异常。  
   - *应对*：使用专用的 `dev_servers.py` 管理脚本以非交互方式启动，并有完备的异常捕获与端口空闲检测，保证环境就绪。
2. **设计系统规则冲突**  
   - *风险*：在修复 A11y 对比度或 Responsive 布局时，可能会不自觉引入高对比度的亮蓝指示器或大圆角，从而破坏古典中国风设计系统的“朱砂罕用”与“碑拓骨力”规则。  
   - *应对*：在每次修复时，严格对照 `DESIGN.md` 中的 Named Rules（如线框胜于阴影、宣纸温润规则），用朱砂红印章或熟宣底色等国风元素替代现代 SaaS 常见组件。
3. **自动化打包与编译失效**  
   - *风险*：修复可能引入 TypeScript 类型报错或超出包体积预算（Bundle Budget）。  
   - *应对*：在大型检查循环中强制运行 `npm run type-check` 和 `npm run build:budget`，防止打包失败。

## 执行方案

1. **启动测试环境**：运行本地开发服务器，确保前端 `http://127.0.0.1:5173`（或备用端口）与后端代理可达。
2. **首轮基线审计**：
   - 检查代码中 hard-coded 的颜色、无 ARIA 标签的交互节点、大圆角等反模式。
   - 使用 `chrome-devtools-mcp` 插件加载登录页、工作区及设置页面，检查响应式断点、移动端横向滚动、元素聚焦和交互。
   - 编写首版审计报告。
3. **针对性问题修复**：按 A11y、性能、主题、响应式及设计反模式分类，使用推荐的 `impeccable` 指令进行重构。
4. **大型检查循环**：每三个任务，彻底执行一次包含类型检查、测试运行、浏览器效果、安全性与文档同步的全面 review。
5. **终期提升审计**：完成所有修复后，再次对五个维度进行等同标准的审计打分，形成对比报告。

## 验证方式

1. **自动化质量检查**  
   - 单元测试：`npm run test:unit`  
   - 编译检查：`npm run type-check`  
   - 打包与预算：`npm run build` 和 `npm run build:budget`
2. **运行态与交互验证**  
   - 使用 Playwright 截图及控制台日志分析，评估加载性能及 JavaScript 异常。
   - 键盘 Tab 键焦点流和无障碍色盲模式下的对比度审查。
3. **审计分数衡量**  
   - 目标：使 Audit Health Score（总分 20 分）获得可量化的显著提升，从基线（可接受/Poor）提升至优秀或良好。

## 回滚方案

1. **Git 精细版本管理**：在开发过程中使用极小的改动颗粒度，每次任务在修改代码前可备份或确信可以通过 Git 命令（如 `git checkout`）直接回滚受影响组件。
2. **轻量化局部修改**：尽量使用 `replace_file_content` 做精准的非侵入式替换，防止误改其他业务逻辑。

## 默认假设

1. 后端服务仅用于提供基本数据接口和鉴权代理，在前端审计修复过程中，后端逻辑和数据存储结构保持稳定，不发生破坏性改变。
2. 审计与测试皆在 Chrome Headless 模式或模拟容器浏览器环境下运行，假定宿主机环境的 Node.js 及 Python 环境配置正确。
