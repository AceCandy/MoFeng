# 增量审计整改

## Goal

在 2026-07-19 已完成治理的基础上，修复本轮审计确认的安全、配置、质量门禁、
发布、可访问性和文档缺口，使下一次公开发布具备可验证、可回滚的准入条件。

## Requirements

- 按 A1、A2、Q1、R1、U1、D1、T1 七个可独立验收的工作包实施。
- A1 与 A2 必须先于下一次公开发布完成；R1 必须等待 Q1 恢复全绿基线。
- 行为改动、机械改动和发布治理改动分批实施，不混入无关重构。
- 安全边界失败时必须关闭功能，不得以进程内状态或跳过门禁降级。
- 总体技术方案、非目标、上线与回滚策略以
  `docs/audit-remediation-design-2026-08-10.md` 为准。

## Out Of Scope

- 不重做 2026-07-19 已完成的 CORS、SSRF、CSP、数据库迁移和资源归属治理。
- 不在单个子任务中顺带完成其他工作包。
- 不改变注册功能的产品默认值，不扩大 mypy 范围，不引入新的 OAuth 会话框架。

## Acceptance Criteria

- [ ] 七个工作包的验收项全部通过，且没有 skip、永久 audit ignore 或假门禁。
- [ ] A1/A2 的配置与 OAuth 安全契约在 focused tests 中可复现。
- [ ] Q1 恢复的全量质量基线可被 R1 作为阻断式发布门禁执行。
- [ ] 最终发布的 Git tag、镜像 digest、metadata 与同一 source commit 一致。
- [ ] 工作树不遗留凭据、测试容器、截图、trace 或本地审计产物。
