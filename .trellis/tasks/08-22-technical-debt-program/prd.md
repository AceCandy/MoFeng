# 全仓技术债治理

## Goal

把已确认、仍未解决的技术债拆成可独立验收的有序子任务，逐项规划、实现、复核和归档，最终完成一次跨任务集成复核。

## Background

- 蓝图/概念对话类型边界与脆弱前端源码字符串测试已在本计划创建前完成，不重复纳入子任务。
- memory-layer 的 `project_id` 外键长度已统一为 `String(36)`，不再作为待修债务。
- 当前剩余债务横跨后端测试基础设施、前端 HTTP/类型边界、Pydantic 迁移、模型默认值审计与死代码删除，不能作为一个不可独立验证的大改提交。

## Requirements

- R1. 父任务维护 8 个子任务的统一范围、执行顺序和跨任务验收；产品代码只在子任务内修改。
- R2. 子任务按下表顺序逐个推进；前一个任务完成检查并归档后，再激活下一个任务。
- R3. 每个子任务在实现前必须完成自己的规划材料并取得用户对最新规划的明确批准。
- R4. 每个子任务必须保持最小 diff、独立验证、独立复核和可单独回滚，不顺带处理未列入范围的债务。
- R5. 父任务最后执行跨子任务集成复核，确认任务之间没有引入新的重复边界、兼容性回归或未记录风险。

## Acceptance Criteria

- [ ] 8 个子任务均有无占位内容的可验收 PRD，并在各自启动前补齐其复杂度所需的规划材料。
- [ ] 8 个子任务均按顺序完成实现、独立检查、提交和归档；每项保留可追溯的验证结果。
- [ ] 各子任务没有扩展到表中未列出的产品功能或相邻重构。
- [ ] 父任务最终复核后，后端与前端的相关质量门禁通过，且未遗留未说明的弃用告警、类型逃逸或死引用。
- [ ] 无法在当前环境验证的项目被明确记录，不以“已完成”代替未执行的验证。
- [ ] 父任务仅在全部子任务完成和跨任务复核通过后归档。

## Out of Scope

- 新功能、用户界面重设计或业务流程调整。
- 已解决的 memory-layer 外键长度问题。
- 未经证据确认的全仓格式化、目录搬迁、依赖升级或数据库迁移。

## Notes

- 父任务不直接承载产品代码实现；其职责是顺序、范围与最终集成复核。
- 子任务树表达归属，前置关系以本 PRD 的有序任务表为准。
