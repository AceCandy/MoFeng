# 全仓技术债治理集成复核设计

## Boundary

父任务只整合 8 个已归档子任务的证据并执行最终质量门禁，不直接修改产品代码。允许的写入仅限父任务验证记录、父 PRD 验收状态，以及修正两个已归档子任务中与既有验证证据不一致的验收勾选。

## Evidence Model

- 子任务状态与顺序以归档目录、`task.json` 和提交历史为准。
- 子任务范围与未验证项以各自 PRD、research 和 journal 为准。
- 当前产品状态以后端、前端质量命令及精确静态扫描为准。
- 历史文档中的旧实现描述保留为历史事实，不按现存死引用处理。

## Integration Checks

1. 流程完整性：8 个子任务均已按父 PRD 顺序规划、实现、复核、提交和归档。
2. 后端整合：快速与 PostgreSQL pytest profile、Ruff、Pydantic v2 弃用告警门禁通过。
3. 前端整合：类型检查、完整单测、lint 和生产构建通过。
4. 债务回归：已治理的认证 HTTP 双边界、目标 `any`、遗留编辑器类型逃逸、提醒死链和 `base.css` 死引用没有回归。
5. 风险透明：环境限制、既有失败或非阻塞预算预警必须写入验证记录。

## Failure and Rollback

- 门禁失败时先判断是否由 8 个子任务引入；属于计划内回归则返回对应范围修复，属于无关既有问题则记录证据，不静默扩大父任务。
- 父任务只产生文档和任务状态提交，可单独回滚，不影响 8 个产品提交。
