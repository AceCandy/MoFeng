# 技术设计

## 变更边界

行为差距集中在共享 AppShell、四处旧视觉残留和四个缺少页面级标题的真实渲染视图。修复只触及前端模板、局部样式、路由元信息及对应回归测试；不改变网络请求、Pinia/Vue Query 状态、路由路径、权限和数据合同。

## 方案

### 1. 账户菜单

- 保留 `userTagRef` 外层容器作为点击外部边界，容器内用原生 `button type="button"` 作为唯一触发器，避免把弹出内容嵌套在按钮中。
- 触发器绑定 `aria-expanded`、`aria-controls` 和稳定菜单 id；既有 CSS 类继续复用。
- 四个导航式动作改成 `button type="button"`，退出按钮保持现状。
- 在账户容器上处理冒泡的 Escape：关闭菜单并聚焦始终存在的触发器。无需新增 document 级键盘监听或菜单抽象。

### 2. 项目上下文颜色

- 删除 `AppShell.vue` 旧项目上下文 scoped 覆盖块，让 `world-class.css` 已有 `.app-shell--project-context` 群青背景与白字规则成为唯一合同。
- 不修改 token，不新增 `!important`，同时释放入口 CSS 预算。

### 3. 旧视觉残留

- 删除纯装饰 DOM、对应计算函数、类型和孤立 CSS；保留业务进度、状态点、Tooltip、无障碍文本及状态数据流。
- 仅替换两组用户可见文案：“墨进度”→“项目进度”，“成/待”→“完成/待补”。
- 不扩大到审查未确认的页面重构或装饰清扫。

### 4. 页面身份

- 现有可见标题直接换成语义标签并复用原 class；写作台以真实渲染的 `ChapterMeta` 章节标题为页面级 `h1`，避免依赖未挂载的 `WDHeader`。
- `SettingsView` 的 hero 只在独立路由渲染，直接改为 `h1`；弹窗标题继续由 `GlobalModalContainer` 的 `h2` 提供。
- 在现有 router 实例上注册 `afterEach`，复用 `meta.label` 生成“页面名 · 墨风”；认证路由补 label，无 label 时回退“墨风”。

## 兼容与回滚

- 所有变更均为前端本地、无迁移；可按 AppShell、旧视觉残留、页面身份三组独立回滚。
- 原生按钮会继承既有菜单项样式；若浏览器复核发现 UA 默认字体或对齐，仅在已有 selector 中补最小 reset，不新建样式层。
- 颜色删除若暴露真实未覆盖节点，只修正共享全局合同，不恢复旧 scoped 块。

## 测试策略

- 在既有 UI 回归测试中先补失败合同：原生账户按钮、无 `javascript:`、Escape 焦点恢复、页面标题/h1、旧视觉标记清退。
- 静态测试覆盖不可回退的源码合同，真实浏览器覆盖键盘、级联颜色、响应式和 axe 结果。
- 一次集中实现后进行一次桌面/移动批量检查；若发现缺陷，合并为一个修复批次并最多再确认一次。
