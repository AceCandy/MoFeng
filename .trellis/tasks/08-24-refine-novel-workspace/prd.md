# 收敛优化小说项目库

## Goal

保留小说项目库现有蓝白双舞台、超大书名和明确品牌冲击，同时减少首屏信息竞争、长标题排版事故与项目列表操作噪声，让回访作者在 3 秒内识别当前作品并继续创作。

## Background

- 用户明确选择“保留现在的视觉冲击，只做收敛优化”，不接受整体换风格。
- 当前页面由 `NovelWorkspace.vue` 的左侧今日创作舞台、`ProjectCard.vue` 的项目行和 `world-class.css` 的最终视觉覆盖共同组成。
- 审查快照 `.impeccable/critique/2026-08-24T11-17-23Z__frontend-src-views-novelworkspace-vue.md` 评分 25/40；主要问题是书名末字孤行、左侧同权信息过多、项目行高饱和操作重复、0% 与“蓝图完成”语义冲突。
- 当前工作树中的 `AppShell.vue` 与 `uiAuditRegression.spec.ts` 账户菜单调整属于前一项直接修改，不扩大或回退其内容。

## Requirements

### R1. 保留视觉世界

- 保持桌面约 42% / 58% 的群青行动面与冷白档案面。
- 保持超大书名、群青结构色和荧黄“继续创作”主动作。
- 不引入新配色、图片、动效、依赖或通用工作台组件。

### R2. 收敛左侧信息层级

- 长中文标题在代表性桌面宽度使用均衡换行，不出现截图中的单字孤行，也不产生横向溢出。
- 保留当前作品、摘要、题材/章节信息、继续创作、新建灵感、今日目标和项目进度。
- 删除底部“创作中 / 待推进 / 最近编辑”快照，因为它与项目列表及进度信息重复。
- 将“今日目标”从同权卡片收敛为轻量提示区，继续保留标题和恢复建议。

### R3. 降低项目列表操作噪声

- 项目标题、元数据、进度和现有详情/继续/删除行为保持不变。
- 项目行“创作”从高饱和填充按钮降为清晰但次级的描边操作。
- 删除按钮默认使用中性色，hover / focus 时再进入错误色；始终保持可见、可聚焦和至少 44px 目标。
- `total_chapters === 0` 时状态改为“蓝图已完成 · 正文未开始”，消除 0% 与“蓝图完成”的歧义。

### R4. 收紧档案区与响应式节奏

- 减少档案标题上方和项目行的过量留白，但保留连续列表与清晰分隔。
- 960px 以下取消固定 hero 最小高度，让项目库自然进入后续阅读流。
- 桌面、833px 中间断点和 Pixel 7 均不得出现横向溢出；DOM、视觉和键盘顺序保持一致。

### R5. 保持现有合同

- 不修改项目查询、创建、删除、继续创作、详情导航或删除确认流程。
- 保留加载、空、错误、进度条 ARIA、键盘焦点、44px 触控目标与 reduced-motion 合同。
- 不修改后端、API、路由、数据库和其他页面。

## Acceptance Criteria

- [ ] AC1：蓝白双舞台、超大书名和荧黄主动作仍是桌面首屏的主要视觉特征。
- [ ] AC2：测试项目“我被武林高手一招打废后”在桌面代表宽度不出现单字末行；更长连续文本可换行且无横向溢出。
- [ ] AC3：左侧不再显示创作快照；今日目标仍可见但不再呈现为与主作品同权的卡片。
- [ ] AC4：首屏唯一高饱和行动是继续当前项目；项目行创作按钮降级但仍清晰可用。
- [ ] AC5：删除操作默认不持续制造红色噪声，hover/focus 风险语义明确，点击仍进入既有确认流程。
- [ ] AC6：未开始正文的蓝图项目显示“蓝图已完成 · 正文未开始”与 0% 进度，不再语义冲突。
- [ ] AC7：桌面、833px 和 Pixel 7 无横向溢出；项目库不会被固定 hero 高度无谓推迟。
- [ ] AC8：针对性单测、类型检查、lint、生产构建预算和工作台桌面/移动 E2E 通过。

## Out of Scope

- 新增项目排序、筛选、搜索、批量操作或“最近继续”功能。
- 改写今日目标计算逻辑或新增工作恢复数据。
- 重构全站顶栏、账户菜单、设置页或视觉 token。
- 清理 `NovelWorkspace.vue` 中被最终样式覆盖的既有暖纸/旧视觉 CSS；避免把历史债务清理混入本次收敛。
