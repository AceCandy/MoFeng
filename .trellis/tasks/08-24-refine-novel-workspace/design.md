# 技术设计：收敛优化小说项目库

## 1. 边界与原则

本任务是现有视觉世界内的 refinement，不是 redesign。数据、路由、事件和组件边界不变，只调整 `NovelWorkspace` 的信息密度、`ProjectCard` 的文案/操作权重，以及 `world-class.css` 中当前实际生效的布局覆盖。

不创建新的 Workspace shell、状态 store、断行函数或响应式 composable。标题均衡使用浏览器原生 CSS，避免为单个页面引入 JavaScript 测量。

## 2. 左侧行动面

### 标题

- 在最终视觉规则中保留 display 字体和大字号，略降字号上限。
- 使用 `text-wrap: balance` 平衡中文换行，配合可断长串的 overflow 规则。
- 不截断作品标题，不用 JavaScript 插入 `<br>`，避免不同标题和宽度产生硬编码断点。

### 信息层级

- 主层：书名、摘要、继续创作。
- 次层：题材/章节、新建灵感。
- 辅助层：今日目标与项目进度。
- 删除 `workspace-hero__snapshot` DOM 及因此产生的无消费者计算；今日目标保留内容，但改为由分隔线和间距组织的轻量区域，不再使用卡片背景与完整边框。

## 3. 右侧档案面

- 保留 `ProjectCard` 的 article、标题 button、进度条和两个事件入口。
- “创作”按钮改用现有 outlined 按钮类，不新增按钮变体。
- 删除按钮保持 DOM 常驻与键盘可达，默认改为中性色，hover/focus 使用现有 error token；不采用仅 hover 显示，避免触屏与键盘发现性下降。
- 修改 `getStatusText` 的零章节文案，不改变进度计算或后端字段。
- 通过最终运行时权威 `world-class.css` 收紧档案 padding、标题字号和项目行纵向节奏；不清理被覆盖的历史 scoped CSS。

## 4. 响应式与无障碍

- 保持桌面 42/58 分栏。
- 960px 以下继续纵向堆叠，但 hero 改为内容自然撑高，不保留 560/500px 最小高度。
- 保持标题与按钮 DOM 顺序、44px 目标、原生 button、progressbar ARIA、删除确认和 reduced-motion。
- 用现有 Playwright user fixture 同时验证桌面 Chromium 与 Pixel 7；视觉检查在一次桌面/移动批次内完成。

## 5. 兼容与回滚

- 无 API、数据库、路由或状态迁移。
- 标题、左侧层级、项目操作和响应式规则可按文件独立回退。
- 若浏览器对 `text-wrap: balance` 不支持，将自然回退到现有换行；仍由 overflow 规则防止横向溢出。

## 6. 方案取舍

- 不隐藏删除按钮：降低颜色权重即可解决噪声，隐藏会增加触屏和键盘复杂度。
- 不把整行改成单一链接：详情与继续创作目前是两个真实行为，合并会改变交互合同。
- 不增加筛选/排序：项目数量增长问题真实但不属于本次视觉收敛。
- 不建立标题断行算法：原生均衡换行覆盖当前问题，JS 测量会增加维护与响应式风险。
