# 整体创作交互体验设计

## Goal

把工作台、灵感、蓝图、项目档案、写作台和后台任务收束成一段连续、可恢复、可预期的长篇创作体验：作者始终知道当前项目、创作阶段和唯一下一步动作，离开后能在同浏览器、跨会话和跨设备恢复语义工作位置。

## Background

- 单一浅色“剧场排演提示本”视觉合同已经稳定，本任务强化交互连续性，不更换视觉世界或主题。
- 工作台当前按项目 `last_edited` 推断“继续创作”，不能表达只浏览、未发送草稿或写作台分区等真实工作位置（`frontend/src/views/NovelWorkspace.vue:364-372`）。
- 写作台只能从 `chapter_number` query 恢复章节，当前分区 `content | versions | evaluation` 是组件内状态，卸载后丢失（`frontend/src/composables/useWritingDeskNavigation.ts:41-85`、`frontend/src/components/writing-desk/WDWorkspace.vue:334`）。
- 已发送灵感对话可由服务端恢复；未发送输入当前在退出时明确丢弃（`frontend/src/views/InspirationMode.vue:419-427,519-583`、`frontend/src/components/ConversationInput.vue:123-189`）。
- 后台任务由数据库与全局 SSE 持久化，离开页面不会中断；任务面板目前只有状态、进度、日志和错误，没有结果回跳或恢复动作（`frontend/src/components/shared/AppShell.vue:41-155`、`frontend/src/components/shared/TaskLogPanel.vue:60-124`）。
- 项目身份已经由 AppShell 展示，项目档案与写作台也已有双向入口；灵感页使用 query project id，尚未纳入同一项目上下文（`frontend/src/components/shared/AppShell.vue:126-255,346-501`）。
- 蓝图确认组件声明了返回事件，但没有可触发的返回控件（`frontend/src/components/BlueprintConfirmation.vue:109-159`）。

## Requirements

### R1. 连续创作路径

- 工作台必须按最近真实工作上下文继续到灵感、项目档案或写作台，而不是只按项目内容更新时间猜测。
- 项目卡标题进入项目档案，主按钮继续创作；不得继续出现“标题看似查看档案、实际进入写作台”的语义错位。
- 灵感、蓝图确认、蓝图展示、项目档案和写作台之间必须都有清晰的前进与返回路径。
- AppShell 在灵感、项目档案和写作台统一显示项目身份与当前阶段；不增加全局向导或常驻步骤条。

### R2. 跨设备语义上下文恢复

- 服务端按用户和项目保存：最近访问页面、最近章节、写作台分区、未发送灵感草稿、对应灵感轮次和更新时间。
- 工作台使用服务端更新时间确定最近项目；项目内恢复到最近页面、章节和稳定分区锚点。
- 不同步像素滚动、抽屉开合、弹窗、候选预览、请求中按钮态或其他瞬时 UI。
- 服务端是跨设备事实来源；本地存储仅在草稿尚未成功同步时作为短期保护，成功后清除，退出账号时不保留。
- 多设备在同一灵感轮次写同一字段时采用最后写入覆盖：以服务端最后成功提交为准，不提示冲突、不保留双副本、不提供合并界面。
- 草稿只能恢复到与保存时相同的灵感轮次；若另一设备已推进对话，旧轮次草稿不得进入新问题输入框。
- 旧轮次草稿写入由服务端静默丢弃并清理，不视为需要用户处理的编辑冲突。

### R3. 状态驱动的唯一主动作

- 工作台、灵感、蓝图和写作台在空、加载、进行中、待确认、成功和失败状态下突出一个唯一主动作。
- 次要动作保持可发现，但不得与主动作争夺朱红视觉 cue。
- 复用写作台现有工作流状态机及命令，不另建第二套章节状态判断。

### R4. 可行动的后台任务反馈

- 任务面板明确说明任务对象、进度和“离开页面不会中断”。
- 有项目归属的运行中或成功任务可回到成果页面；章节任务在能安全解析章节号时回到对应章节。
- 失败的章节工作流回到对应章节，由写作台现有状态机提供允许的重试、重同步、取消或重置动作；不新增虚假的通用重试/取消接口。
- 无安全导航目标的内部治理任务继续只展示日志，不依据私有 payload 猜测路由。

### R5. 响应式、键盘与动效合同

- 桌面与移动端保持等价任务能力；新增控件满足既有焦点恢复、键盘操作、触控尺寸和无水平溢出合同。
- 只使用一套“阶段签轻落”的短暂阶段切换反馈；它不阻塞操作、不依赖颜色表达状态，并在 `prefers-reduced-motion` 下退化为静态变化。

### R6. 变更边界

- 复用现有 Vue Query、Pinia、SSE、路由、AppShell、写作台工作流与视觉 token。
- 允许新增最小后端数据表、鉴权 API、迁移与生成的前端合同。
- 不新增依赖、主题、设计系统、实时协同通道或与核心路径无关的功能。

## Acceptance Criteria

- [ ] 无项目、有未完成灵感、已有普通项目三种工作台状态分别呈现一个正确的主动作，并进入最近语义位置。
- [ ] 项目卡标题进入 `/projects/:id`，继续按钮按最近上下文进入灵感、项目档案或带章节 query 的写作台。
- [ ] 灵感页显示当前项目/阶段；蓝图确认态可返回对话；退出文案不再错误声称未发送草稿必然丢失。
- [ ] 设备 A 保存项目、章节、分区和草稿后，设备 B 在重新进入/刷新时恢复；重新聚焦时仅在本机字段未修改的情况下应用远端值。
- [ ] 两台设备在同一灵感轮次先后保存同一字段时，读取结果等于服务端最后成功提交；全流程不出现冲突弹窗或合并界面。
- [ ] 远端对话已推进到新轮次时，旧轮次未发送草稿不会恢复到新问题。
- [ ] 最近上下文更新时间并列时仍以稳定次序选出同一项目；跨设备测试不得依赖数据库未承诺的默认顺序。
- [ ] 写作台恢复有效章节和可用分区；章节或分区失效时安全回退到首个可用章节和 `content`。
- [ ] 后台任务运行时可安全离开；成功任务可查看成果；失败章节任务可回到写作台的现有恢复动作。
- [ ] 任务列表、snapshot 与 SSE 不公开私有 payload；仅公开通过任务类型白名单校验的可导航章节号。
- [ ] 桌面与 Pixel 7 视口无能力缺失或水平溢出；新增动作可键盘访问且焦点可见。
- [ ] 普通动效短暂且只在阶段变化时触发；减少动态效果模式下无持续动画且状态仍清晰。
- [ ] 后端聚焦测试、OpenAPI/生成合同检查、前端类型检查、单元测试、双设备 E2E、lint 与 build 通过，或明确记录已有基线失败。

## Out of Scope

- 实时多人或多设备协同编辑、WebSocket 草稿广播、冲突历史、双副本与手工合并。
- 像素滚动位置、抽屉、弹窗、候选预览和请求中瞬时状态同步。
- 命令面板、复杂手势、拖拽编排、新 AI 功能或新的通用任务重试/取消系统。
- 更换视觉方向、主题切换或扩张装饰性动效。
