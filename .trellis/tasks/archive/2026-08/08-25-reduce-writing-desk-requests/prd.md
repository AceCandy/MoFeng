# 减少章节详情页重复请求

## Goal

减少写作台首次打开章节详情时的重复网络请求和非关键首屏请求，让正文更快进入可用状态，同时保留任务流、章节状态和创作上下文的正确同步。

## Background

- 项目详情缓存键是章节缓存键的前缀；项目失效会连带失效章节。
- 章节工作流同时刷新项目与章节，因此当前前缀失效会造成章节重复刷新。
- 首次工作流快照和首次任务列表快照可能把历史状态视为新变化。
- 全局任务已使用 SSE，同一时间仍固定每 15 秒轮询。
- TTS 配置和无变化的创作上下文写入不是正文首屏的必要条件。

## Requirements

1. 项目详情失效只命中项目详情自身，不连带章节及其他子查询。
2. 章节工作流首次快照只建立修订号与边界基线；只有后续真实变化才刷新项目和章节。
3. AppShell 首次任务快照只记录已完成大纲任务；只有后续新完成任务才刷新项目数据。
4. 任务 SSE 正常连接时不执行固定轮询；SSE 未连接或断开时保留 15 秒兜底轮询。
5. 写作台选择当前已选章节时不重复写入相同创作上下文。
6. TTS 配置在首次需要模型语音能力时加载，不作为章节正文首屏请求。
7. 保留现有用户改动，不改后端响应结构，不引入新依赖或新抽象。

## Acceptance Criteria

- [x] 刷新项目详情不会使同项目的章节查询失效。
- [x] 初始工作流快照不会调用 `invalidateChapterAndProject`，后续修订或边界变化仍会调用。
- [x] 初始历史任务快照不会触发项目刷新，新完成的大纲任务仍会触发。
- [x] SSE 激活时任务列表无定时轮询，断线时恢复 15 秒兜底。
- [x] 重复选择当前章节不会发出创作上下文 PATCH。
- [x] 创建章节阅读器不立即请求 TTS 配置；首次播放或显式刷新仍能获取配置。
- [x] 相关 Vitest 用例与前端类型检查通过。

## Out of Scope

- 后端项目/章节响应瘦身。
- 新增写作台 bootstrap API。
- 历史版本、生成日志的独立懒加载接口。
- UI 布局或视觉样式调整。

## Risks and Deferred Items

- 前端去重完成后，单次项目详情和章节详情响应仍然偏大；需要通过后续 API 瘦身任务解决。
- SSE 连接状态必须与轮询开关共用现有状态，避免断线后失去兜底刷新。
