# 修复首次候选描红稿重复展示

## Goal

首次生成章节且尚未选定正式版本时，只展示一份 AI 候选描红稿，避免同一候选同时被误呈现为落墨正文和描红稿，让作者能准确识别内容是否已经定稿。

## Background

- 章节没有正式 `content` 时，现有版本解析会从 `availableVersions` 取候选内容作为展示正文。
- 待选版阶段又会把同一候选作为描红预览传入内容组件，导致上下重复。
- `WDWorkspace.vue` 已有 `hasFinalizedChapterContent`，可以区分真实正文与版本兜底内容，无需改变全局版本解析行为。

## Requirements

- 首次生成且存在描红预览、但没有正式章节正文时，不渲染落墨正文区域和“候选描红稿”分隔线。
- 已有正式章节正文时，继续同时展示落墨正文与新候选描红稿。
- 没有描红预览时，继续允许历史版本作为正文兜底展示。
- 修改范围限制在前端展示边界及其聚焦回归测试，不改变 API、持久化或候选生成流程。

## Acceptance Criteria

- [x] 正文为空、版本兜底内容与描红候选相同时，页面只渲染一个 `data-provenance="ai"` 候选区域。
- [x] 上述场景不渲染 `data-provenance="ink"` 正文区域，也不显示“候选描红稿”分隔线。
- [x] 正文非空且候选存在时，正文与候选两个区域仍同时显示。
- [x] 没有候选预览时，现有历史版本兜底展示保持不变。
- [x] 聚焦前端回归测试通过。

## Out of Scope

- 不处理后端生成出与既有正式正文完全相同候选的去重问题。
- 不调整描红稿视觉样式、文案、落墨动画或候选选择交互。
- 不重构 `useVersionResolver`。

## Risks

- 修复必须仅在描红预览存在且真实正文为空时屏蔽版本兜底，避免破坏旧章节依赖历史版本读取正文的兼容行为。
