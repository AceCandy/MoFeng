# 逐页精修全部前端页面

## Goal

对全部九个可达前端页面及其核心子视图做一次有边界的逐页精修，补齐此前 P0/P1 修复之后仍存在的 P2、视觉一致性、响应式、状态与交互细节，使“全部页面已优化”具有明确覆盖清单和浏览器证据。

## Background

- 路由表包含 `/login`、`/register`、`/workspace`、`/inspiration`、`/projects/:id`、`/projects/:id/write`、`/settings`、`/admin`、`/admin/novels/:id` 九个页面；旧 `/detail/:id`、`/novel/:id`、`/admin/novel/:id` 为兼容重定向，不是独立视觉页面。
- `08-22-fix-ui-audit-findings` 已处理九页审查中的 P0/P1 功能、移动端和无障碍问题；`08-23-single-paper-theme` 已将全站收敛为单一暖纸浅色主题。本任务不重复这些改动，只修仍可复现的缺口。
- 设计继续遵循 `PRODUCT.md` 与 `DESIGN.md` 的安静写作台、暖纸、描红界格体系；这是 refinement，不是整站重设计。

## Requirements

1. 为九个页面建立逐页覆盖清单，并覆盖页面内实际可达的主要分区、抽屉、弹窗、设置/管理标签页和项目详情分区。
2. 每页至少检查桌面 `1440×900` 与移动端 `390×844`；只在存在独立断点行为的共享壳、项目详情和写作台补查临界宽度。
3. 按优先级修复仍可复现的问题：阻塞任务或误导状态 → 空态/加载/错误/禁用/权限状态 → 层级与响应式 → 视觉与动效一致性。
4. 精修覆盖信息层级、间距与对齐、中文排版、表单与按钮状态、触控尺寸、键盘焦点、可访问名称、横向溢出、对比度、控制台错误和页面状态恢复。
5. 共享问题修在现有 token、共享壳或共享组件的正确归属处；局部问题只改所属页面。不新增依赖、主题抽象或一次性设计系统。
6. 保留现有业务流程、API、路由语义、设计语言和已通过的测试合同；除第 8 项明确批准的导航辅助外，不借机重写文案、重构数据层或新增业务能力。
7. 为改变了可观察行为的修复补最小回归测试；纯视觉微调复用现有浏览器与静态合同，不新建重复测试套件。
8. 允许增加不涉及后端的客户端导航辅助：写作台章节搜索/章号跳转，以及管理 Prompt 搜索和移动端“列表→编辑”模式；复用现有输入、按钮、响应式与状态模式。

## Acceptance Criteria

- [x] 九个页面及兼容重定向均有明确验收记录，不能以“继承全局主题”代替逐页检查。
- [x] 每个页面在桌面与 `390×844` 下主任务清晰、无横向溢出、无内容遮挡或不可达控制；共享壳和工作区在相关临界断点无跳变回归。
- [x] 页面核心加载、空态、错误、成功、禁用、长内容和权限受限状态按实际可构造范围完成检查，未覆盖项明确记录原因。
- [x] 键盘焦点、Tab 顺序、触控目标、弹层焦点管理、标题/地标和 WCAG 2.1 AA 对比度无新增问题。
- [x] 所有修复继续使用暖纸浅色 token，九页不出现近黑大块、暗色分支、硬编码同义色或新的视觉体系漂移。
- [x] 前端 lint、类型检查、全量 Vitest、相关 Playwright/E2E、Impeccable detector 和最终 source diff 复核通过。
- [x] 浏览器复验无新增脚本错误；调试服务关闭，截图、报告、会话状态和其他临时产物不进入提交。

## Out of Scope

- 后端 API、数据结构、鉴权规则或业务流程变更；若审查发现此类问题，只记录，不在本任务扩范围修复。
- 新页面、未在第 8 项明确列出的功能、整站重新设计、新主题、新依赖或与当前九页无关的代码清理。
- 为无法由现有 fixture/测试数据可靠构造的破坏性生产场景制造真实数据；使用现有 fixture、mock 或非破坏性验证。

## Technical Notes

- 页面模式以 Operate 为主；认证页承担进入产品的辅助 Persuade，但不采用营销页风格。
- Impeccable polish 采用一次成批初审、一次集中修复、最多一次复验，避免无限循环打磨。
- 旧审查报告仅作为线索；所有问题必须在当前代码与浏览器中重新确认后才能进入修复清单。
