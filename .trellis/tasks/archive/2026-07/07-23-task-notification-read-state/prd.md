# 任务通知红点已读状态

## Goal

让导航栏任务图标准确表达后台任务的聚合状态：排队任务不提醒，执行中任务持续显示数量，成功或失败结果显示可清除的完成提醒。用户查看任务日志后，仅清除成功/失败提醒，后续新的完成结果再次提醒。

## Background

- `AppShell.vue` 通过 `useTasksQuery()` 和 `useTaskStream()` 接收后台任务列表及 SSE 快照。
- 当前导航图标在存在运行中任务时显示数量，在没有运行中任务但存在失败任务时显示红点。
- 当前实现没有“已查看”状态，因此失败任务存在期间红点不会因用户查看而消失，也没有成功结果提示。
- `BackgroundTask` 已提供稳定的 `id`、`status`、`created_at`、`updated_at` 等字段，无需修改后端接口。
- `AppShell.vue` 及相关样式、回归测试存在用户未提交改动，本任务必须保留并基于这些改动做最小增量修改。

## Requirements

- R1：`queued` 任务不在导航图标上显示提醒。
- R2：存在 `running` 任务时，导航图标持续显示运行中任务数量，最多显示 `9+`；点击查看不清除该运行状态。
- R3：没有运行中任务时，未查看的 `succeeded` 结果显示绿色完成提醒，未查看的 `failed` 结果显示红色失败提醒。
- R4：同时存在未查看的成功和失败结果时，失败提醒优先显示。
- R5：用户点击任务图标并打开任务日志后，当前成功/失败结果标记为已查看，对应提醒立即消失。
- R6：标记已查看后出现新的成功或失败结果时，对应提醒再次显示。
- R7：已查看状态应按当前登录用户保存在浏览器本地，刷新页面后不得重新提示已经查看的完成结果。
- R8：不新增后端字段、数据库表或任务 API；不改变任务日志面板内容。
- R9：沿用现有 CSS token、图标位置和无障碍命名，不新增装饰动画。

## Acceptance Criteria

- [ ] AC1：任务列表为空或只有 `queued` 任务时，任务图标不显示状态提醒。
- [ ] AC2：存在 `running` 任务时显示运行中数量，点击查看后只要任务仍在运行，数量继续显示。
- [ ] AC3：没有运行中任务且存在未查看的成功结果时，显示绿色完成提醒。
- [ ] AC4：没有运行中任务且存在未查看的失败结果时，显示红色失败提醒；成功和失败同时未查看时显示失败提醒。
- [ ] AC5：点击任务图标打开日志后，当前成功/失败提醒立即消失。
- [ ] AC6：在没有后续完成结果时，关闭弹窗或刷新页面不会使已查看提醒重新出现。
- [ ] AC7：标记已查看后出现新的成功或失败结果，对应提醒再次出现。
- [ ] AC8：不同登录用户的已查看状态互不影响。
- [ ] AC9：相关单元测试覆盖排队、运行、成功、失败、标记已读、后续完成结果和用户隔离。

## Out of Scope

- 后端跨设备同步成功/失败结果的已读状态。
- 逐条任务或逐条日志的已读管理。
- 任务日志面板视觉重构。
- 修改任务 SSE 或查询 API。

## Technical Notes

- 这是轻量前端任务，采用 PRD-only 计划。
- 已查看状态使用按用户命名空间隔离的 `localStorage` 记录已查看的终态任务标识，不引入全局状态或后端持久化。
- 运行进度和日志更新不产生额外提醒；提醒只由 `running` 聚合状态及新的 `succeeded` / `failed` 终态结果驱动。
