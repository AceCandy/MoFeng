# 章节朗读与 TTS 模型接入

## Goal

为已完成章节提供一键朗读能力，并在“乾坤万象中枢”中增加语音朗读模型配置。用户配置默认 TTS 模型时优先使用服务端 TTS；未配置时自动使用浏览器原生语音合成。

## Background

- 已完成章节工具栏位于 `WDWorkspace.vue:L37-L62`，当前包含复制和导出操作。
- 可朗读正文应使用 `selectedChapterResolvedContent`（`WDWorkspace.vue:L833-L849`），它已统一处理正文、版本兜底与内容清洗。
- 设置中枢由 `SettingsView.vue:L58-L165` 驱动，当前只有文本生成、记忆检索和阶段路由三个 Tab。
- 现有模型配置只支持 `chat`、`embedding` 能力，`llm_config_service.py:L111-L116` 会丢弃其他能力。
- 仓库目前没有浏览器朗读、音频播放或 TTS 服务实现。
- 小米官方 `XiaomiMiMo/MiMo-Skills` 已确认 MiMo V2.5 TTS 契约：Base URL 为 `https://api.xiaomimimo.com/v1`，使用 Chat Completions；待合成文本放入 `assistant` 消息，`audio` 指定 `wav` 和预置音色，响应音频位于 `message.audio.data` 的 Base64 数据中。
- `mimo-v2.5-tts` 的预置音色为冰糖、茉莉、苏打、白桦、Mia、Chloe、Milo、Dean；官方建议超过 2500 字时才考虑按句段切分。

## Requirements

- 仅在章节已完成且存在可用正文时显示朗读按钮。
- 朗读支持开始、暂停、继续和停止；切换章节或离开页面时停止并释放当前朗读资源。
- “乾坤万象中枢”新增“语音朗读”Tab，可维护具备 `tts` 能力的供应商和模型，并选择唯一默认 TTS 模型。
- 配置默认 TTS 模型时，章节朗读通过认证后的后端代理调用供应商，API Key 不下发浏览器。
- 未配置默认 TTS 模型时，使用浏览器 `speechSynthesis` 朗读当前章节。
- 已配置 TTS 但合成失败时，自动回退浏览器朗读，并明确提示用户已发生回退及失败原因摘要。
- TTS 能力和默认模型需贯通前端类型、后端 Schema、服务层、ORM、历史数据库兼容更新与 SQL 结构说明。
- TTS 调用使用独立语音服务/适配器，不复用绑定创作阶段的聊天模型路由。
- 首版提供两种明确的模型级 TTS 协议：MiMo Chat Completions 音频协议，以及 OpenAI `/v1/audio/speech` 兼容协议；不支持用户自定义任意请求模板。
- 默认 TTS 模型保存默认音色与语速；已知模型提供音色选项，同时允许兼容供应商填写自定义音色 ID。
- 章节工具栏只承担播放控制，不在每次朗读前重复询问音色或语速。
- 长章节按自然段和句子自动切分，首段生成完成后立即开始播放，并按顺序生成、播放后续分段。
- 浏览器朗读使用相同的文本分段队列，规避浏览器对超长 `SpeechSynthesisUtterance` 的中断问题。
- 朗读内容按“当前章节标题、当前章节正文”的顺序组成。
- MiMo 协议实现遵循小米官方 Skill 的 Chat Completions 音频契约，不使用 `/v1/audio/speech` 假定替代。

## Acceptance Criteria

- [ ] 已完成且有正文的章节右上角显示朗读按钮，其他章节状态不显示。
- [ ] 朗读按钮能正确驱动开始、暂停、继续、停止状态，且重复点击不会产生并发朗读。
- [ ] 切换章节、关闭工作台或组件卸载后不再播放旧章节内容。
- [ ] 设置中枢显示可键盘访问的“语音朗读”Tab，并能配置唯一默认 TTS 模型。
- [ ] 配置默认 TTS 模型时使用服务端返回的音频；未配置时使用浏览器朗读。
- [ ] TTS 合成失败时自动切换浏览器朗读，并显示非静默的回退提示。
- [ ] 不支持 `speechSynthesis` 的浏览器给出明确不可用反馈。
- [ ] TTS 配置按用户隔离，不能读取或调用其他用户的模型与密钥。
- [ ] TTS 能力保存后不会被归一化逻辑丢弃，默认 TTS 模型保持唯一。
- [ ] 同一配置体系可分别保存并调用 MiMo 协议模型和 OpenAI Speech 兼容协议模型，运行时不依赖模型名称猜测协议。
- [ ] TTS 设置可保存默认音色和语速；再次朗读时直接使用保存值，无需弹出额外配置。
- [ ] 超长章节会完整、按序朗读；首段合成后即可开始，不需要等待整章音频全部生成。
- [ ] 每次朗读先播报当前章节标题，再按原文顺序播报正文。
- [ ] 后端正确处理第三方鉴权失败、超时、空音频、超长正文和不受支持的响应格式。
- [ ] 前后端相关单元测试、类型检查与构建通过。

## Out Of Scope

- 语音克隆和声音设计模型的专用工作流。
- 将 API Key 现有明文存储机制整体改造成加密存储。
- 音频文件持久化、离线下载与跨章节播放列表。
